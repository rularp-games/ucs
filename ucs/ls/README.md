# Веб-интерфейс игрока: «Потеряно соединение со спутниками»

Прототип поста игрока для ЛАРП. Игрок входит по коду сеанса и позывному, на
«посту» проходит четыре модели тренировок (синхронизация), добывает карты
сопротивления жетонами и тратит их на пакеты информации и рацию. Мастер ведёт
сеанс из отдельной панели.

Правила — в репозитории игры (`rules/sync.md`, `models.md`, `resistance.md`,
`information.md`); они остаются источником правды, здесь лежит только их
реализация и заглушки текстов персонажей.

## Устройство

Контент (YAML) и правила (`engine.py`) не зависят от Django. Состояние сеанса
хранится в базе: игроки, синхронизация, карты, покупки, жетоны, эфир.

| Файл | Что делает |
| --- | --- |
| `data/game.yaml` | контент: символы, пакеты программы, шаблон звена из 6 персонажей, замки досье |
| `loader.py` | разбор YAML в неизменяемые объекты + проверка целостности |
| `engine.py` | чистые функции: цепочка открытия, уровни, генераторы и проверки четырёх моделей, порядок досье, коды жетонов |
| `models.py` | `Game`, `Flight`, `Player`, `Token`, `Purchase`, `RadioMessage`, `TaskAttempt` |
| `services.py` | создание игры, жетоны, траты карт, отказ, запись попыток |
| `views.py`, `urls.py` | страницы игрока и панель мастера |
| `templatetags/ls_extras.py` | значки символов и силуэты целей (inline SVG) |
| `templates/ls/` | шаблоны; CSS в `base.html`, JS прямо в страницах моделей |
| `tests.py` | тесты |

Внешних библиотек и CDN нет: в кластере нет интернета. Вся графика — inline SVG.

### Как работает задача

Сервер генерирует задачу со случайным seed и кладёт её в сессию игрока
(`ls_task_<параметр>`). Ответ приходит POST'ом, сервер проверяет его по
сохранённой задаче функциями `engine.check_*`, пишет `TaskAttempt`, обновляет
синхронизацию и показывает «Выполнено» или «Провал». Правильного ответа в
HTML нет. Повторный POST после проверки ничего не меняет: задача уже снята.

Модель «Строй» (`move`) принимает результат от JS как есть, но проверяет, что с
момента выдачи задачи прошло не меньше требуемого времени (отметка времени
сервера лежит в сессии).

### Правила, которые стоит помнить

- Параметр открыт, если он `nav`, или его синхронизация больше нуля, или
  предыдущий параметр не ниже 50. Поэтому отказ по `nav` не закрывает уже
  начатый `move`.
- Отказ даёт карту сразу, а не при следующем уходе в темноту, как в бумажных
  правилах. Если синхронизация параметра уже равна нулю, карта не выдаётся.
- Замки досье: жизнь 25, смерть 70, попадание 100 минут. Значение для жизни
  взято из `information.md`, в ТЗ его не было; оно лежит в `dossier_locks`
  YAML и меняется без правки кода.
- До старта игры закрыты все замки со временем; пакеты без замка (имя
  персонажа) выдаются.
- Пакет «О себе» № 1 тоже стоит карту (в бумажных правилах его читает ИМП на
  вводной).
- Время сеанса игроку не показывается, только мастеру.

## Как запускать

Из корня репозитория:

```shell
python3 -m venv .venv
.venv/bin/pip install django==5.2.8 djangorestframework==3.15.2 drf-spectacular==0.28.0 \
    celery==5.4.0 django-celery-beat==2.8.1 redis==5.2.1 pyyaml==6.0.2
cd ucs
../.venv/bin/python manage.py migrate
../.venv/bin/python manage.py createsuperuser     # логин и пароль придумайте сами
../.venv/bin/python manage.py runserver
```

Полный `pip install -r requirements.txt` нужен только для продакшена
(`uwsgi` и `psycopg2_binary` собираются не везде). Локально
`ucs/private_settings.py` указывает на sqlite (`ucs/db.sqlite3`); пароль
суперпользователя нигде не хранится.

Адреса:

| Адрес | Что |
| --- | --- |
| `/ls/` | вход игрока: код сеанса и позывной |
| `/ls/post/` | пост: символ, четыре параметра, карты |
| `/ls/post/model/<параметр>/` (nav, move, parts, fire) | модель тренировки |
| `/ls/post/tokens/` | ввод кодов жетонов |
| `/ls/post/cards/` | траты карт |
| `/ls/post/known/` | «Что я знаю» |
| `/ls/radio/` | «Эфир» (нужна рация) |
| `/ls/master/` | панель мастера (только `is_staff`) |

### Создать игру и войти игроком

1. Войдите в `/admin/` суперпользователем, затем откройте `/ls/master/`.
2. «Новая игра»: название, код (например `demo`), контент `game`, число звеньев.
   Создаются звенья, 6 игроков на звено и 100 жетонов (по 20 на символ).
3. На странице игры нажмите «Старт». Кнопки ±5 мин сдвигают игровые часы, это
   открывает пакеты с замками по времени.
4. Лист жетонов (`/ls/master/<игра>/tokens/`) печатается: коды сгруппированы по
   символам, использованные зачёркнуты.
5. Игрок открывает `/ls/`, вводит код игры и позывной (`Семь-Три`; при нескольких
   звеньях с суффиксом: `Семь-Три-Б`). Позывные видны в таблице мастера.

В таблице мастера синхронизацию, карты и рацию игрока правят кнопками, журнал
попыток и покупок открывается по позывному.

## Что заглушка

- Тексты персонажей (память и досье) помечены «[заглушка]»: персонажи ещё не
  написаны. Тексты программы взяты дословно из `rules/information.md`.
- Позывные и символы персонажей — рабочий набор для прототипа.
- Модель «Строй» принимает результат клиента как есть, с проверкой только по
  времени. Параметры физики шарика подобраны на симуляции, не на живых людях.

## Вне прототипа

- Парные варианты моделей (двое соседей по звену).
- Звук (падение шарика, объявление ИМПа «Автоматика»).
- Настоящая авторизация: вход по коду и позывному, без пароля.
- Автообновление панели мастера (страница обновляется кнопкой).
- Приём жетонов «в темноте» на выходе: здесь игрок вводит коды сам.
